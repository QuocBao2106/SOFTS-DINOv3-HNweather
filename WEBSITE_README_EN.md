# HanoiWeather AI — Web Deployment Bundle

This bundle adds a lightweight FastAPI backend and a responsive, tab-based Vietnamese weather website to the official SOFTS repository. It is designed to be copied into the root of your existing SOFTS checkout, beside `models/`, `layers/`, `utils/`, and `exp/`.

## Features

- Current conditions and five-day weather information from the Open-Meteo Forecast API.
- A 24-hour forecast endpoint backed by the trained SOFTS model.
- A Vietnamese single-page interface with tab navigation rather than one long scrolling page.
- Model status and historical SOFTS evaluation metrics.
- FastAPI health endpoint and interactive API docs.

## Required model files

The SOFTS prediction endpoint requires all three matching artifacts in:

`checkpoints/HanoiWeather_SOFTS_FINAL_168_24/`

- `checkpoint.pth`
- `scaler.pkl`
- `config.json`

Use artifacts from the same training run. Do not combine a checkpoint and scaler from different folders. The artifacts are not bundled here because they are generated by your training run.

## Local run

Use Python 3.11 in the root of the SOFTS repository:

```bash
pip install -r requirements-web.txt
# Only if torch is not installed yet, install a CPU build:
# pip install torch --index-url https://download.pytorch.org/whl/cpu
uvicorn app:app --host 127.0.0.1 --port 8000 --reload
```

Open `http://127.0.0.1:8000`. Health: `/api/health`; API documentation: `/docs`.

## Deploy to Render

1. Add these files and your matching, reasonably sized model artifacts to your GitHub repository.
2. In Render, create a **Web Service** connected to your repository and select the branch containing these files.
3. Render reads `render.yaml` for the build command, start command, and health check. The service starts with Uvicorn on the assigned port.
4. After a successful deployment, Render provides a public `onrender.com` URL. Confirm `/api/health` and `/api/status` before sharing the website URL.

If Git ignores `checkpoints/`, check `.gitignore` and explicitly add only the intended final artifacts. Do not commit access tokens or unrelated datasets. If a checkpoint exceeds GitHub's ordinary file limit, use Git LFS or a controlled artifact store and configure the deployment path accordingly.

## Data and scientific limitations

Current conditions and multi-day forecast cards come from Open-Meteo. The SOFTS model was trained on ERA5 data ending in 2025; live inference uses the most recent available hourly sequence from Open-Meteo, so the input distribution is not identical to the training data. The SOFTS prediction must therefore be labelled experimental until it has been evaluated prospectively against observed weather. Historical MAE/RMSE values are backtest metrics, not guarantees for live conditions. The app does not retrain the model automatically when a visitor opens the site; retraining should be a separate, checked workflow.
